# CLAUDE.md

Briefing for Claude Code sessions on Vera View. The README covers features, building and
packaging; this file records context, decisions and status that aren't obvious from the code.

## What this is

Vera View: a read-only viewer for Visio Open XML drawings (.vsdx/.vsdm/.vstx/.vstm), in Rust
with eframe/egui 0.36. Windows, Linux and macOS. Owner: Jeff Remec (GitHub: jridder).
Public repo https://github.com/jridder/vera-view, MIT licensed. Website (privacy policy,
support, downloads) is a separate public repo, jridder/vera-view-site, served by GitHub Pages
at https://jridder.github.io/vera-view-site/.

## Working on it

- Run: `cargo run --release -- FILE.vsdx`. Test drawing: `cargo run --example make_sample`
  writes `samples/sample.vsdx` (git-ignored). Timings: `cargo run --release --example inspect -- FILE`.
- Check like CI: `cargo clippy --all-targets -- -D warnings` and `cargo test`. Code must stay
  warning-free on all targets; cross-check with `--target aarch64-apple-darwin` /
  `x86_64-unknown-linux-gnu` (type-checks without linking).
- Visual checks without a human: the app has `--screenshot OUT.png` (renders ~30 frames,
  saves, exits), plus `--view X,Y,ZOOM%`, `--page N`, `--find TEXT`, `--about`, `--notices`.
  Use these and look at the PNG rather than assuming rendering is right.
- Icons and Store logos are generated: `cargo run --example make_icon` (writes `assets/`).
- Match the existing style: long lines are fine (no rustfmt config is used), comments explain
  why, not what.

## Decisions already made (don't revisit without asking)

- Read-only viewer only; .vsdx family only (legacy binary .vsd unsupported, with a clear error).
- Mouse wheel scrolls, Ctrl/⌘+wheel and pinch zoom (Visio behaviour).
- Trademark: "Visio" is used only descriptively ("Microsoft® Visio® files"). Attribution line
  "Microsoft and Visio are trademarks of the Microsoft group of companies." plus a
  non-affiliation statement appear in the About box, start screen, exe metadata, README,
  Store listing and website. Never put "Visio" in the app name, logo or store keywords.
- Open-source notices: `THIRD-PARTY-NOTICES.txt` is generated by cargo-about from
  `about.toml` (allow-list of licenses; MIT preferred for dual-licensed crates; covers all
  three platforms). It's embedded in the app via `include_str!`, so it must stay committed.
  Build scripts regenerate it; a new license type fails the build on purpose.
- Commits use the GitHub noreply identity: `Jeff Ridder <11082465+jridder@users.noreply.github.com>`.
  This is repo-local git config, so set it again in any new clone:
  `git config user.name "Jeff Ridder"` and
  `git config user.email "11082465+jridder@users.noreply.github.com"`.
- Microsoft Store identity (must match Partner Center exactly; in
  `installer/msix/AppxManifest.xml`): Name `JeffRemec.VeraView`, Publisher
  `CN=F46F4FA3-D687-4828-A525-1CB9E0D1CF4B`, PublisherDisplayName `Jeff Remec`.
  MSIX versions are four-part with a trailing 0 (0.3.0 → 0.3.0.0).

## Releasing

Bump `version` in Cargo.toml, optionally add `docs/releases/vX.Y.Z.md`, commit, then
`git tag -a vX.Y.Z -m "Vera View X.Y.Z"` and `git push origin vX.Y.Z`. CI checks the tag
matches Cargo.toml, builds all packages and publishes the GitHub release. The Store package is
built separately on Windows with `installer/build-msix.ps1` and uploaded in Partner Center
(not attached to GitHub releases).

## Gotchas found the hard way

- epaint mitres closed polylines without limit, causing spikes when zoomed out; strokes are
  drawn as open paths that wrap past the start (see `viewer.rs`).
- Visio `ArcTo` bow: positive bulges to the right of the direction of travel (matches libvisio).
- egui windows fade in; screenshots must wait several frames or dialogs look translucent.
- makepri's default config splits display scales into separate resource packages, which only
  work in bundles; `build-msix.ps1` removes the `<packaging>` section so one resources.pri
  holds every logo variant.
- On Windows PowerShell 5.1, `gh ... --jq` expressions with quotes or spaces get mangled;
  pipe JSON to `ConvertFrom-Json` instead.
